# Python 是动态类型还是强类型？变量换了类型，对象也会改变吗？

> 作者：程序员Sunday · [Sunday面试指南](https://note.lgdsunday.club/)
>
> [在线阅读与配图](https://note.lgdsunday.club/python/q565-python-dynamic-strong-typing/) · [题库目录](../../README.md)

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：Python 是动态类型语言，那是不是也属于弱类型？

🙋‍♂️ 我：我理解是类型不需要提前写，所以变量里可以放不同的值。

🧑‍💻 面试官：同一个变量先放整数，再放字符串，原来的整数对象变成字符串了吗？

🙋‍♂️ 我：应该是变量换了一个对象。

🧑‍💻 面试官：那为什么字符串加整数会报错，整数加浮点数却可以？

> 把两个问题拆开看就好理解了。名字能绑定哪些对象，和一次运算允许哪些类型参与，分别由不同规则决定。

## 面试速答（60 秒版）

Python 通常被称为动态类型、强类型语言，这两个说法讨论的事情不同。

动态类型说的是，变量名不需要一直绑定某一种类型。比如 value 先指向整数，后来又指向字符串，这两次赋值都可以。变化的是名字和对象之间的绑定，原来的整数并没有被改造成字符串。

强类型这个说法，主要是在提醒我们，运算仍然要遵守类型规则。字符串和整数直接相加会报错，需要先明确是做数值加法，还是拼接文本，再进行转换。

但是，这不代表 Python 完全没有隐式转换。整数和浮点数一起运算就有对应规则。因此，面试时最好把具体行为讲出来，别只用动态、强弱这几个标签判断代码会不会成功。

## 知识点详解：变量能换对象，运算仍有自己的规则

### 先看两次赋值究竟改了哪里

假设一个接口先读到数量 12，后来又从输入框读到文本“12”。这两个结果看起来差不多，但它们是两种对象。

写下 value = 12 时，名字 value 绑定到一个整数对象。再执行 value = "12"，这个名字就改为绑定字符串对象。前一个对象的类型没有因此改变；如果还有其他名字引用它，其他名字仍然可以读到原来的整数。

所以，平时说“变量的类型变了”，可以当作方便的口头说法。解释机制时，最好再补一句，变的是当前绑定，类型属于对象。Python 官方数据模型把对象的身份、类型和值分开说明，普通重新赋值不会把这些概念合到一起。

![第二次赋值，只换了 value 的指向](https://note.lgdsunday.club/img/Q565/02-bindings.webp)

### 动态类型没有取消运算要求

接着把文本“12”加上整数 1。这里就需要做一个决定了，到底要得到数字 13，还是文本“121”？

Python 的字符串加法要求另一边也是字符串，因此直接写 "12" + 1 会得到 TypeError。开发者可以用 int 转成数值，再做加法；也可以用 str 转成文本，再拼接。转换之前还要确认输入格式，int("12个") 就不会成功。

下面把这几个动作放在一起。TypeScript 示例额外展示 JavaScript 的运行时拼接规则，两边的加法行为并不相同。

#### Python

```python
value = 12
original = value
value = "12"
print(type(original).__name__, type(value).__name__)  # int str
print(int(value) + 1)       # 13
print(value + str(1))       # 121
try:
    print(value + 1)
except TypeError:
    print("类型不符合字符串加法的要求")
```

#### TypeScript（JavaScript 运行时对照）

```typescript
let value: number | string = 12;
const original = value;
value = "12";
console.log(typeof original, typeof value); // number string
console.log(Number(value) + 1);             // 13
console.log(value + 1);                     // "121"
```

这一处特别容易混淆。TypeScript 在执行前做静态类型检查，实际加法仍按照 JavaScript 的规则运行。不能因为给项目加了 TS，就说运行时转换规则也一起改了。

![先决定要数字，还是要文本](https://note.lgdsunday.club/img/Q565/03-conversion.webp)

### 为什么整数和浮点数又能一起算？

因为这种组合有明确的数值运算规则。例如 12 + 0.5 能得到浮点结果，不能据此认定“Python 会把任意类型都自动转换”。

强类型和弱类型没有一套所有语言都采用的精确分界线。讨论接口输入时，比标签更有用的问题是，这个值现在是什么类型，当前运算是否支持它，如果需要转换，失败时应该怎样处理。

也别把字符串和整数相加是否报错，当作语言类型系统的全部。自定义类还能实现运算方法，同一个加号在不同对象上可能有不同含义。本文只用内置字符串和数值解释边界，不把这个例子扩大成对所有类型的保证。

### 接口输入要在哪一步确认类型？

假设接口约定 quantity 是一个正整数。那么从外部拿到数据以后，就应该在入口完成解析与校验，再让后面的计算使用确认过的数据。

只写 quantity: int 这样的类型注解，并不会自动拒绝所有不合规输入。Python 的类型提示和运行时校验分别承担不同工作，后面会在类型注解与 Pydantic 题中继续讲。

检查这一层可以准备整数、数字字符串、空字符串、None 和带单位的文本，观察每种输入走到了哪个分支。这样才能说清系统到底接受什么，而不是笼统地说“强类型很安全”。

依据：[Python 3.11 数据模型](https://docs.python.org/3.11/reference/datamodel.html)、[Python 3.11 数值与序列类型](https://docs.python.org/3.11/library/stdtypes.html)、[TypeScript 类型擦除说明](https://www.typescriptlang.org/docs/handbook/2/basic-types.html)。

## 面试官继续追问

### 加了类型注解，就变成静态类型语言了吗？

运行时仍按 Python 的规则执行。类型检查器可以在运行前发现部分问题，但是否拒绝接口输入，要看实际校验代码。

### 动态类型是不是不适合大型项目？

项目能否维护还取决于接口约定、类型检查、测试和模块设计。变量允许换对象，不等于项目必须到处随意换类型。

### int 转换成功，就代表数量合法了吗？

还要检查范围和业务约束。解析得到一个整数，只完成了类型层面的处理，负数或过大的数量仍可能不合要求。

## 面试速记卡

> - 动态类型关注名字的绑定，类型属于当前对象。
> - 重新赋值通常换绑定，原对象不会因此变成另一类型。
> - 运算是否合法，要看参与对象与运算规则。
> - Python 允许规则明确的数值转换。
> - 外部输入需要实际解析和校验，类型注解不会代劳。
