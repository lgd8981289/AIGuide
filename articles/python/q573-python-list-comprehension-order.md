*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：Python 列表推导式里两个 for，是同时遍历两个列表吗？

🙋‍♂️ 我：我会把它理解成两个循环的简写。

🧑‍💻 面试官：如果左边有两项，右边有三项，会得到两项、三项，还是六项？

🙋‍♂️ 我：嵌套起来应该是六种组合。

🧑‍💻 面试官：那 if 写在第一个 for 后面，和写在第二个 for 后面，筛选的是同一个阶段吗？

> 先把推导式还原成普通循环，逐层确定变量什么时候得到值，if 在哪个阶段决定继续。

## 面试速答（60 秒版）

列表推导式可以把“遍历输入、筛选成员、生成结果”写在一个表达式里。读取时先按从左到右的 for 和 if 理解执行过程，最前面的结果表达式在条件满足以后才计算。

两个 for 通常对应嵌套循环，右边循环在每次左边迭代里执行。它们不会自动把两个列表按位置配对，也不会因此并行。

if 放在不同位置，筛选时已经得到的变量和能跳过的工作也不同。想同时拿到两个输入的一对成员，通常要明确使用 zip 等配对方式。

因此，简单转换与筛选可以用推导式；需要复杂分支、副作用或读起来难以跟上的嵌套时，展开普通循环更容易维护。

## 知识点详解：先展开循环，再压缩写法

### 从最普通的收集结果开始

假设我们要从几个数字里挑出大于 1 的数字，再计算平方。普通循环先拿到一个数字，检查条件，条件满足才把平方放进结果列表。

推导式把这些动作压在一起，结果表达式写在前面，遍历和筛选写在后面。阅读时却仍要先弄清后面的遍历与筛选，不能按纸面位置认为平方最先计算。

这也是为什么 \[convert(x) for x in rows if valid(x)] 可以先筛选，再转换。被过滤掉的项不会为了生成结果而先调用 convert。

### 两个 for，对应的是嵌套关系

假设 left 是 \[1, 2]，right 是 \[2, 3]。下面在每一个 x 下遍历全部 y，再留下 x 不等于 y 的组合。

#### Python

```python
left, right = [1, 2], [2, 3]
pairs = [(x, y) for x in left for y in right if x != y]
print(pairs)  # [(1, 2), (1, 3), (2, 3)]
expanded = []
for x in left:
    for y in right:
        if x != y:
            expanded.append((x, y))
assert pairs == expanded
```

#### TypeScript（显式循环对照）

```typescript
const left = [1, 2], right = [2, 3];
const pairs: [number, number][] = [];
for (const x of left) {
  for (const y of right) {
    if (x !== y) pairs.push([x, y]);
  }
}
console.log(pairs); // [[1, 2], [1, 3], [2, 3]]
```

所以这里先产生四个候选组合，再筛掉 (2, 2)，得到三个结果。它没有把 1 和 2 配成第一对、2 和 3 配成第二对，那是另一种配对需求。

![两层循环，先组合再筛选](https://note.lgdsunday.club/img/Q573/02-nested-v2.webp)

### if 的位置决定筛选阶段

在 for x in left 后面紧接 if valid(x)，就可以先排除不合规的 x。这个 x 被排除以后，它对应的内部 y 循环也不会开始。

如果条件放在内部 for y 后面，程序已经拿到了这一次 y，条件可以同时使用 x 和 y，但内部遍历已经发生了。即使两种写法在某个样例里得到相同结果，调用次数和副作用也可能不同。

还有一种 if ... else ... 写在结果表达式里，它是在生成结果时选择哪个值，并没有把成员从结果里过滤掉。把条件表达式和过滤条件混在一起，是阅读推导式时常见的卡点。

![外层先筛掉，内部循环就不用开始](https://note.lgdsunday.club/img/Q573/03-filter.webp)

### 简短不保证更快，也不适合所有过程

推导式最终会收集出列表，因此结果规模仍会占内存。它没有因为写在一行里就变成生成器，也没有让耗时计算自动并行。

对于简单的纯转换，推导式往往清楚。条件越多、状态修改越多，就越需要考虑读者能不能顺着一行代码推下去。尤其是里面调用了会写数据库或改变共享状态的函数时，展开循环会更容易检查执行顺序。

验证嵌套写法，可以用空输入、各一项、存在重复值的输入，先写普通循环当作对照，再确认结果和函数调用次数一致。不要只看两段代码最后打印的数字相同。

依据：[Python 3.11 列表推导式](https://docs.python.org/3.11/tutorial/datastructures.html#list-comprehensions)、[Python 表达式中的推导式](https://docs.python.org/3.11/reference/expressions.html#displays-for-lists-sets-and-dictionaries)。

## 面试官继续追问

### map 一定比推导式快吗？

不能这样保证。函数调用、实现和数据规模都会影响结果，先按可读性选择，再对关键路径测量。

### 输入是一次性迭代器，嵌套循环有什么影响？

内部来源可能在第一次外层循环时耗尽，下一次不会自动重新开始。需要重新迭代时明确重建或缓存输入。

### 把 if 放到结果表达式里，结果数量也会减少吗？

条件表达式通常只是选择当前要输出的值。真正过滤成员的是遍历子句后面的 if。

## 面试速记卡

> - 先读 for/if 的执行顺序，再读结果表达式。
> - 多个 for 通常对应嵌套，不是配对或并行。
> - 过滤条件的位置决定哪些工作可以跳过。
> - 结果里的 if/else 选值，过滤 if 决定是否保留。
> - 列表推导式收集结果，复杂副作用宜展开循环。
