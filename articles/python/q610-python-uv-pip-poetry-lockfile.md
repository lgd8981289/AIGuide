# Python 的 uv、pip 和 Poetry 怎么选？pyproject.toml 与锁文件分别管什么？

>
> [在线阅读与配图](https://note.lgdsunday.club/python/q610-python-uv-pip-poetry-lockfile/) · [题库目录](../../README.md)

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：uv、pip 和 Poetry 怎么选？

🙋‍♂️ 我：pip 常用于安装包，uv 和 Poetry 可以管理项目依赖与环境。

🧑‍💻 面试官：pyproject.toml 写了版本范围，为什么两次安装可能选不同版本？

🙋‍♂️ 我：因为声明允许一段范围，还没有固定具体解析结果。

🧑‍💻 面试官：有锁文件就一定跨系统完全一致吗？uv sync --locked 和 --frozen 又有何区别？

> 先分清三份东西。项目允许哪些依赖、这次解析选了哪些版本、当前环境真正装了什么，需要各自检查。

## 面试速答（60 秒版）

pyproject.toml 可以声明项目元数据、依赖范围、构建配置和工具配置。锁文件则记录相应工具解析出来的版本与依赖关系，用来提高重复安装的一致性。

pip 的核心是安装与解析，也有较新锁定能力，但它不是与 uv、Poetry 完全相同的一体化项目工作流。uv 和 Poetry 把环境、项目依赖及锁定组织得更紧，具体命令和锁格式不能混用。

选工具时我会看团队已有项目、发布方式、Python 版本与平台要求，不用一个未经测量的速度倍数决定。

还要检查锁的新鲜度和实际同步。uv 的 --locked 要求锁不需要更新，--frozen 则使用现有锁而不检查是否与声明一致。锁文件也不能替代系统库和运行测试，跨平台结果要结合环境标记与兼容制品判断。

## 知识点详解：依赖声明、解析结果与实际安装环境

### 声明范围，表达的是允许集合

假设项目允许某依赖大于等于一个版本、低于下一主版本。这个范围不是唯一版本；后续出现新的符合版本，两次全新解析就可能不同。

pyproject.toml 的 project.dependencies 可以表达这种要求，还能保存 Python 版本约束。build-system 负责构建工具要求，tool 下保存具体工具配置，不要把所有段落都当成应用运行依赖。

库项目经常需要给使用者保留兼容范围，应用部署则希望固定解析与制品。两类项目的依赖发布目标不同，不必把全部声明写死才叫规范。

### 锁文件保存解析，不是另一份手写愿望

uv.lock 和 poetry.lock 都服务各自工具的解析流程，不是简单把顶层依赖名字再抄一遍。它们还能涉及间接依赖、环境条件和来源信息。

修改了 pyproject，却没更新锁，会让声明和安装意图分开。CI 应该选择会检查这一关系的命令，让不一致直接失败，而不是默默在部署时重新选版本。

同样，pip freeze 记录当前已安装环境，并不自动解释哪些是直接依赖、哪些只是开发机器额外安装的工具。它是有用快照，但要清楚快照来源。较新 pip 的锁能力也需要按实际版本和目标环境核对，不用“pip 永远没有锁”这类过时对比。

### 用命令明确锁和同步的要求

下面是已有 uv 项目中的操作示意，前提是项目配置和锁文件已经存在。不要在一个不相干仓库里直接运行同步命令。

```bash
# 检查声明与锁是否一致，并按锁同步项目环境
uv sync --locked

# 使用已有锁，但跳过锁的新鲜度检查
uv sync --frozen

# 在 uv 管理的项目环境中运行测试
uv run --locked python -m pytest
```

uv sync 默认的精确同步会处理环境里不属于目标依赖的额外包，因此同步也不是只加不减。依赖组、extras 和是否安装项目本身，都需要按命令参数确认。

Poetry 的锁定与安装命令有自己的合同，不能把 uv 的参数直接搬过去。pip 方案也能配合明确版本、哈希与环境管理完成可靠安装，但需要把这些步骤组织起来。

### 锁文件提高可复现性，不消除平台差异

一个依赖在 Linux 和 macOS 可能选择不同 wheel，某些依赖仅在特定 Python 版本或平台生效。锁中的条件是为了表达这些差异，不意味着安装目录字节级完全一样。

编译器、系统动态库和外部服务还不在普通 Python 依赖锁的全部范围内。需要可复现部署时，继续记录 Python、工具版本、平台、安装选项和构建制品，并在目标环境做测试。

工具选择可以从现有项目平滑维护开始。已经有稳定 Poetry 流程时，不必为了热度立刻迁移；新项目想统一环境、运行与锁工作流，可以评估 uv；轻量安装和兼容已有脚本时，pip 仍有价值。本题没有在当前项目做速度基准，不给固定提速倍数。

## 面试官继续追问

### --frozen 是更严格的吗？

它跳过锁与声明的新鲜度检查，不应直接称为更严格。CI 是否要求一致，要选相应检查方式。

### 锁里有版本，就不用运行测试了吗？

版本固定不等于代码、系统库和行为兼容，仍要在实际环境测试。

### 应用和库都应该把依赖钉死吗？

应用部署常锁具体解析结果；库发布需要表达支持范围，让使用者解析兼容组合，两者目标不同。

## 面试速记卡

> - pyproject 声明项目要求和工具配置。
> - 锁文件记录解析结果与相应条件。
> - 当前环境是否符合锁，需要实际同步检查。
> - uv --locked 检查是否需更新，--frozen 跳过新鲜度检查。
> - 锁不替代平台、系统库与运行验证。
