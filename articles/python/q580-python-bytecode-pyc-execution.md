# Python 代码是怎么执行的？字节码、pyc 和解释器分别做什么？

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：Python 是解释型语言，所以完全没有编译步骤吗？

🙋‍♂️ 我：我以前会理解成解释器一行行读取源文件执行。

🧑‍💻 面试官：那 dis 显示的指令是什么？pyc 又保存了什么？

🙋‍♂️ 我：Python 源代码也会先形成可执行的代码对象和字节码。

🧑‍💻 面试官：既然已经有 pyc，再次启动进程就不用执行模块顶层代码了吗？

> 把源代码转换、编译结果缓存和模块执行分开。省掉一段准备工作，不代表模块的运行结果也被保存了。

## 面试速答（60 秒版）

以 CPython 为例，源代码会经过解析和编译，形成代码对象，其中包含字节码等执行所需信息，再由解释器运行。

pyc 可以缓存编译后的代码，常见位置是 **pycache**。缓存可用时，导入模块可以减少重新编译的工作，但新进程仍需要执行模块的顶层代码。

因此，pyc 不是已经计算好的模块结果，也不是可以脱离 Python 运行时直接执行的通用机器码。它不能保证整个程序会明显提速，收益还要看启动与导入成本。

讨论内部指令时要说明解释器和版本。Python 不同实现可以有不同执行方式，dis 的具体输出也会随版本变化。

## 知识点详解：缓存的是代码，运行结果还要重新产生

### 源文件先变成可以执行的代码对象

假设一个函数做两数相加。源文件里的字符先需要被解析成符合语言规则的结构，再形成解释器能够执行的代码对象。

代码对象里包含指令、常量以及名称等信息。调用函数时，还要准备当前执行使用的参数与局部状态。字节码描述要做哪些动作，不会提前知道以后每次调用传进来的数字。

这也是为什么“解释型”不能直接翻译成“从来不编译”。解释器执行编译后的中间表示，与编译器产生独立机器程序，是不同层次的安排。

### dis 可以看到指令，但指令不是固定教材

下面用标准库观察一个小函数。输出中的具体指令名和布局，以运行版本为准。

#### Python（CPython 3.11 基线）

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
print(add(1, 2))  # 3
```

#### TypeScript（源码处理阶段对照）

```typescript
function add(a: number, b: number): number {
  return a + b;
}
console.log(add(1, 2)); // 3
```

TS 编译通常产生 JavaScript，并去除这类类型注解，随后 JS 引擎还有自己的执行准备。它不是 Python pyc 的同名实现，这里只对照“源码处理”和“运行”可以是不同阶段。

看 dis 时，重点理解读取参数、完成运算、返回结果的关系，不把一组指令编号当成所有版本都不变的规则。

![指令说明动作，参数在运行时加入](https://note.lgdsunday.club/img/Q580/02-stack.webp)

### pyc 省掉编译，顶层代码仍会执行

假设 report.py 顶层有一条 print，同时定义了几个函数。一个新进程导入它，解释器即使能够使用缓存的编译结果，仍然要执行 print，并建立当前进程里的模块状态。

另一个新进程再导入，也需要自己的模块对象和状态。pyc 没有把第一个进程的变量值、连接和已执行标记打包给它。

同一个进程正常重复导入通常命中 sys.modules，那才可能直接复用已经加载的模块对象。它与磁盘上缓存编译代码的 pyc 要分开，完整导入机制在下一组文章继续展开。

![有编译缓存，新进程仍执行模块](https://note.lgdsunday.club/img/Q580/03-cache-v3.webp)

### 缓存什么时候能用，为什么不能保证整段程序加速？

源文件变化、缓存校验方式、解释器版本和运行配置都会影响编译缓存能否使用。没有写入缓存权限也不表示源代码就不能执行，可能只是无法保存那份缓存。

pyc 主要帮助减少相应准备阶段的工作。如果程序的大部分时间花在查询数据库或复杂计算，省掉一点导入编译，未必明显改变总耗时。

直接运行的主脚本与被导入模块，缓存处理也有区别；不要把“执行过一次就一定生成同样 pyc”当作语言保证。验证时用两个独立进程导入同一个小模块，观察顶层输出，再检查缓存文件，才能同时确认缓存和执行是两回事。

依据：[Python 3.11 编译后的模块](https://docs.python.org/3.11/tutorial/modules.html#compiled-python-files)、[Python 3.11 dis](https://docs.python.org/3.11/library/dis.html)、[Python 导入系统](https://docs.python.org/3.11/reference/import.html)、[TypeScript 类型擦除](https://www.typescriptlang.org/docs/handbook/2/basic-types.html#erased-types)。

## 面试官继续追问

### 只把源文件改后缀为 pyc，可以得到缓存吗？

不可以。pyc 有对应格式与编译内容，改文件名不会完成编译。

### 分发 pyc 就能保护源码机密吗？

不能把字节码当成保密机制。它仍可能被分析，敏感凭据也不应放进分发代码。

### 能用 pyc 证明某函数已经执行过了吗？

不能。缓存代码和调用函数是不同动作，是否执行需要实际日志、状态或测试证据。

## 面试速记卡

> - CPython 有解析和编译步骤，再由运行时执行。
> - 代码对象和字节码描述动作，参数与状态在运行时准备。
> - pyc 缓存编译结果，不缓存模块运行成果。
> - sys.modules 的进程内复用与 pyc 的磁盘缓存不同。
> - 内部指令和缓存细节按实现、版本与配置核对。
