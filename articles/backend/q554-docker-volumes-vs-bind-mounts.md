# Docker 的 Volume 和 Bind Mount 有什么区别？容器删除后数据还在吗？

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：Volume 和 Bind Mount 有什么区别？

🙋‍♂️ 我：都是把容器数据存到宿主机，删容器就不会丢。

🧑‍💻 面试官：那容器自己可写层里的文件呢？匿名卷配合 --rm 呢？

🙋‍♂️ 我：这些情况我没有分开看。

🧑‍💻 面试官：再问，用远程Docker，bind mount路径指的是你的电脑，还是daemon所在机器？

> 先问文件实际写到哪里，再问这份存储由谁管理、什么时候会被清理。

## 面试速答（60 秒版）

`Volume` 是 Docker 管理的数据存储，容器通过挂载路径使用它。`Bind Mount` 则把 Docker daemon 宿主机上的指定文件或目录映射进容器。

容器可写层随容器删除而丢失；挂载的数据有自己的生命周期。命名卷通常可以在删除容器后继续使用，但不能说所有卷都永不删除，匿名卷的自动移除和其他清理操作需要单独检查。

实际选型中，应用生成的持久数据通常可以考虑 Volume；开发源码或需要明确宿主路径的文件，更适合 Bind Mount。两者都需要权限、备份与恢复设计。

还要留意，挂载到已有内容的目录，会遮住原来的文件。看到容器里文件不见了，要先检查Mounts，不能立刻认定镜像没打进去。

## 知识点详解：容器路径背后，可能是三份不同的存储

### 先区分镜像、可写层与挂载目录

假设镜像里自带配置，容器运行后写入临时日志，又把数据库数据目录挂到命名卷上。这三份东西虽然都能在容器路径里看到，生命周期却不同。

镜像提供基础文件，可写层保存这次容器运行产生的修改，挂载目录则来自另一份存储。删除容器会删除它的可写层，不等于同时删除所有挂载数据。

因此数据能不能保留，要先追文件写到了哪个路径，那个路径是否确实挂载。只写了配置文件，并不能证明应用正在使用它。

### Volume 的名字，是重新找到数据的入口

假设数据库挂载命名卷 `course-data`。容器重建后，挂上同一卷，才会重新看到那份数据。如果新容器创建了另一份空卷，旧数据即使仍在，也不会自动出现在眼前。

匿名卷也有独立数据，只是使用随机名称，重建时更容易忘记重新关联。使用 `--rm` 创建容器时，关联的匿名卷可随自动清理被移除；命名卷不按这一规则自动删除。

所以“删除容器不丢数据”必须带条件。还要检查具体清理命令、Compose选项和卷是否被主动删除。本文不建议直接在生产运行清理来验证。

![容器换了，仍要挂同一份数据](https://note.lgdsunday.club/img/Q554/02-volume-lifecycle.webp)

### Bind Mount 依赖的是daemon所在机器

开发时把项目目录挂进容器，修改宿主文件就能让容器看到。这种方式很方便，但也把容器配置与宿主路径、文件权限联系起来。

如果Docker daemon在远程服务器，挂载源路径来自那台服务器，不是发命令的笔记本。Docker Desktop还会通过自身机制将本机目录提供给虚拟机里的daemon，不能据此推断远程Docker也能随便访问客户端文件。

Bind Mount默认可写时，容器也可能修改宿主文件。只需要读取配置的场景，可以考虑只读挂载，并避免映射过大的宿主目录。

![挂载路径在daemon那一端](https://note.lgdsunday.club/img/Q554/03-remote-host.webp)

### 文件没有消失，可能只是被挂载遮住

假设镜像 `/app` 原本有代码，现在把一个空宿主目录挂到 `/app`。容器看到的是挂载目录，原镜像内容被遮蔽了，所以应用可能报找不到入口文件。

这时要看 `docker inspect` 的Mounts，确认源、目标、类型及读写设置。重新创建一个不带该挂载的测试容器可以帮助判断，但生产容器要按变更流程处理。

Volume在挂载空卷时还有默认复制目标目录内容的行为，并可用相应选项控制。不要因此把Volume和BindMount的初始化细节当成一样。

![挂载会遮住原目录内容](https://note.lgdsunday.club/img/Q554/04-mount-cover.webp)

### 持久化还不是备份

数据留在卷里，只解决容器生命周期问题。如果宿主磁盘坏了、程序误删了记录，卷本身不会替我们恢复。

数据库备份还要保证一致性。直接拷正在写入的数据目录，可能拿不到可恢复的状态。我们需要按数据库支持的方式备份，并实际做恢复验证。

因此选型最终要同时回答，数据在哪里、谁能修改、怎样迁移，以及出错后从哪里恢复。

![留下数据，还要能恢复](https://note.lgdsunday.club/img/Q554/05-backup.webp)

## 面试官继续追问

### Volume一定是本地磁盘吗？

不是。存储驱动和配置可能连接其他后端，不能把Docker管理与本地物理介质画等号。

### 把源码挂进生产容器好吗？

要看发布策略。开发便利不等于生产默认；生产通常还要考虑镜像版本一致性、宿主依赖、权限和回滚。

## 面试速记卡

> - 可写层：随容器移除，不承担长期数据保存。
> - Volume：Docker管理，重新使用要关联同一份卷。
> - Bind Mount：引用daemon宿主路径，注意权限与可写范围。
> - 生命周期：匿名卷自动清理与命名卷不同，别说卷永不删除。
> - 可靠性：持久化不等于备份，恢复必须验证。
