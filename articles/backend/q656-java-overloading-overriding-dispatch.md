# Java 重载和重写有什么区别？编译期选方法和运行时多态怎样配合？

下面是一段模拟面试对话。

🧑‍💻 **面试官：** Java 的重载和重写有什么区别？

🙋‍♂️ **我：** 重载是同名方法、参数不同；重写是子类重新实现父类方法。

🧑‍💻 **面试官：** 父类类型的变量指向子类对象，调用时到底听谁的？

🙋‍♂️ **我：** 应该调用子类的方法。

🧑‍💻 **面试官：** 子类另外新增了一个参数更具体的重载，也会自动选中它吗？

> 一次调用分两步：先选中哪一个方法签名，再确定这个签名由哪个实现执行。

## 面试速答（60 秒版）

Java 重载是在同名方法里，根据参数列表等信息区分不同签名。编译器会结合接收者和参数的声明类型，判断有哪些方法可用，再选择适用的方法。不能只靠返回类型不同来重载。

重写则是子类为继承来的实例方法提供自己的实现。编译期选好签名以后，对适用动态分派的实例调用，运行时会根据接收者实际对象的类型，决定执行哪个重写实现。

因此，不能简单说“调用时全部看实际类型”。实际对象是子类，并不会让编译器重新选择参数更具体的重载。静态方法隐藏、字段访问和构造器，也不能按普通实例方法重写来解释。

## 知识点详解：把方法签名和方法实现拆开看

### 先看一个能暴露区别的调用

假设 Base 定义 `show(Object x)`。Child 一方面重写这个方法，另一方面又新增 `show(String x)`。

现在变量写成 `Base receiver = new Child()`，再执行 `receiver.show("hello")`。这时最容易误判：参数是字符串、对象又是 Child，于是一定执行 Child 的 String 版本。

但编译器先看到的是 Base 类型的 receiver。它会在这个类型能访问的方法中选择签名，最终选中的是 `show(Object)`。运行时再根据实际的 Child 对象，执行 Child 重写后的 Object 版本。

**运行时多态接管的是已选签名的实现，并没有重新做一次重载选择。** 这两步的规则可分别参照 [JLS 方法调用表达式](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.12)与[方法重写和隐藏](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.4.8)。

### 参数变量的声明类型，也会影响重载

继续假设接收者就是 Child。如果参数变量声明为 Object，即使里面装着一个字符串，编译器也不能默认把它当成 String 选择重载。

想改变可用的静态信息，需要显式转换或通过类型检查把变量收窄。但转换又会引入运行时类型检查，不能为了调用某个重载随便强转。

这和 JavaScript 运行时根据 typeof 自己写分支，不是同一套语言机制；Python 的普通方法也不会自动获得 Java 式同名重载。因此本文保留 Java 签名示例，不配一套含义不同的 TS/Python“对应实现”。

![父类引用，怎样调用到子类实现？](https://note.lgdsunday.club/img/Q656/02-java-overloading-overriding-dispatch.webp)

### 重载选择不只是比较谁的类型更窄

Java 还涉及严格调用、装箱拆箱和可变参数等适用阶段。一个方法名下面塞进过多重载，调用方就很容易被隐式转换影响。

特别是传 null 时。如果有 String 和 StringBuilder 两个互不构成子类型关系的重载，null 同时能匹配它们，编译器却无法选出唯一更具体的方法，调用会出现歧义。

所以重载适合表达一组含义一致、调用方式清楚的接口。两个行为如果本来就不同，换成两个明确的方法名，往往比让调用方猜规则更好。

### 重写也有约束

重写不等于“名字一样就覆盖”。方法签名、访问范围、返回类型和异常声明都有规则。例如访问权限不能随意缩小，返回类型在满足规则时可以协变。

`@Override` 的价值就在这里：让编译器检查你确实重写了预期方法。否则参数拼错，可能只是悄悄新增了一个重载，父类调用路径仍然走原来的实现。

## 面试官继续追问

### 静态方法能重写吗？

静态方法属于方法隐藏的讨论范围，调用选择不按接收者实例的运行时类型分派。代码最好通过类名调用，避免用实例写法制造“好像也有多态”的错觉。

### 怎么检查自己没有只背定义？

把接收者声明类型、对象实际类型、参数声明类型列成三列，再分别预测签名和实现。测试至少覆盖父类引用指向子类、Object 参数装 String、null 歧义和静态方法。本文只给推导，不冒充已经在本机编译出全部字节码。

## 面试速记卡

> - 重载：编译期选择适用签名，返回类型不同不构成重载。
> - 重写：对适用的实例调用，运行时选择已选签名的具体实现。
> - 声明类型：影响接收者可见方法和参数匹配。
> - 实际类型：不负责重新选择一个更具体的重载。
> - 易错点：静态方法是隐藏，字段和构造器也别套实例重写规则。
