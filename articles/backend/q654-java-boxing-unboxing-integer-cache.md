下面是一段模拟面试对话。

🧑‍💻 **面试官：** Integer 和 int 之间可以直接赋值，为什么？

🙋‍♂️ **我：** Java 会自动装箱和拆箱。

🧑‍💻 **面试官：** 两个 Integer 都是 100，用 == 比较是什么结果？换成 1000 呢？

🙋‍♂️ **我：** 小整数可能共用缓存对象，不能一直用 == 比较数值。

🧑‍💻 **面试官：** 那一个值为 null 的 Integer，执行“等于 0”的判断，是得到 false，还是直接报错？

> 先看这次操作需要的是对象还是基本数值。装箱会涉及对象身份，拆箱则要求那个对象真的存在。

## 面试速答（60 秒版）

自动装箱，就是编译器在需要包装类型的位置，把基本类型转换成对应包装对象；自动拆箱则是从包装对象中取出基本值。

Integer 的装箱通常通过 valueOf 完成，它会复用一定范围的小整数对象。Java 21 的 Integer API 保证至少缓存 -128 到 127，范围之外不能依赖对象是否相同。

两个 Integer 用 == 比较，通常是在比较引用；但 Integer 和 int 比较，会发生拆箱，再比较数值。所以只换一个操作数的类型，含义就可能不同。

拆箱的风险在于 null。一个 Integer 没有对象，却被拿去做算术或与 int 比较，就会抛出空指针异常。实际开发中要先确定“缺失”怎么处理，再做数值运算，不能指望自动拆箱帮我们补一个 0。

![装箱看对象，拆箱要有值](https://note.lgdsunday.club/img/Q654/01-java-boxing-unboxing-integer-cache.webp)

## 知识点详解：同一个 ==，为什么会出现不同结果？

### 装箱让基本值进入需要对象的位置

比如集合保存的是 Integer，而我们加入一个 int。源代码看起来只写了一次添加，编译器会补上相应转换，让基本值进入包装对象所代表的类型体系。

这不等于每次都 new 一个对象。valueOf 可以返回已有缓存对象，减少常见小整数的重复创建。[Integer.valueOf 的 API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Integer.html#valueOf\(int\))给出了保证范围。

也正因为对象可能被复用，不能拿“小整数比较正好相等”的结果，总结出所有 Integer 都按值执行 ==。

![两个 100，可能拿的是同一个对象](https://note.lgdsunday.club/img/Q654/02-java-boxing-unboxing-integer-cache.webp)

### 比较之前，要先写出操作数的类型

下面讨论 Java 的语言语义，不提供名称相近但行为不同的 TS 或 Python 伪实现。

| 操作数               | 实际需要区分的事                    |
| ----------------- | --------------------------- |
| 两个 int            | 直接比较基本数值                    |
| 两个 Integer 引用     | == 判断是否为同一个对象               |
| 一个 Integer、一个 int | Integer 拆箱后参与数值比较           |
| Integer.equals    | 检查符合该包装类型规则的值相等，不是通用跨数值类型比较 |

假设两个变量都是通过装箱得到的 Integer，值都是 100。在保证的缓存范围里，它们可以引用同一个对象。

换成 1000 就不要写死结果。你要回答的是“不依赖这个引用比较判断数值”，而不必把某次 JVM 的默认配置当成所有环境的保证。

顺便注意，Integer 的 1 和 Long 的 1L，不能因为数学上相等，就认为 Integer.equals 会返回 true。比较前应该先明确类型和业务含义。

### null 为什么会在一个看似安全的判断里炸掉？

假设接口字段 count 是 Integer，缺失时为 null。

你写下 `count == 0`，可能只是想判断是不是零。但右边是 int，左边需要先拆箱，效果相当于先从 count 对象里取出 int 值。对象都不存在，这一步就已经失败，根本还没轮到比较。

同样的风险还会出现在 `count + 1`、一些条件表达式，以及把包装值传到要求基本类型的参数位置时。[JLS 对拆箱转换的定义](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.1.8)明确说明，null 的拆箱会抛出 NullPointerException。

### 缺失不一定等于零

处理方法不是遇到 null 就全部替换成 0。

假设一个字段表示“本月已确认的付款金额”，0 可能代表确认过、金额就是零；null 则可能代表还没计算。直接默认成 0，会把两种不同状态混在一起。

因此，先决定字段是否允许缺失。必须有值的字段，在输入处拒绝缺失；允许缺失的字段，在运算前明确分支。数值相等判断也要选择能表达预期 null 语义的方法。

![缺失值，不能偷偷变成零](https://note.lgdsunday.club/img/Q654/03-java-boxing-unboxing-integer-cache.webp)

## 面试官继续追问

### 包装类型能不能用作锁对象？

不要拿缓存的包装对象当私有锁。你以为自己拿到的是局部对象，其他代码却可能通过相同值拿到同一个引用，造成意外竞争。需要锁时，用用途清楚、身份稳定的专用对象。

### 怎么验证自己有没有把引用和数值混起来？

测试里同时覆盖缓存内、缓存外、不同包装类型以及 null。比较的每一侧都写清声明类型。若要观察编译器转换，再看对应 JDK 的字节码，但不要把反编译后的某个形态当成语言唯一实现。

## 面试速记卡

> - 装箱：基本值进入包装类型，不保证每次新建对象。
> - 缓存：Integer 至少保证 -128 到 127，不依赖范围外的引用身份。
> - 比较：两个包装引用的 ==，和包装对象对基本值的 ==，含义不同。
> - 拆箱：null 没有可取出的基本值，会抛空指针异常。
> - 工程处理：先定义缺失语义，再决定是否默认成零。
