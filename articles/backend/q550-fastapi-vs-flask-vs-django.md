*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：Python 后端，你会选 FastAPI、Flask，还是 Django？

🙋‍♂️ 我：做接口选 FastAPI，轻量项目选 Flask，大项目选 Django。

🧑‍💻 面试官：我们要登录、权限、管理后台和一套接口，怎么选？

🙋‍♂️ 我：项目比较大，那就 Django。

🧑‍💻 面试官：如果 Flask 写了 async，能不能因此说它跟 ASGI 应用有同样的并发方式？

> 选框架先数要自己补多少能力，再检查这些能力在实际运行栈里怎样工作。

## 面试速答（60 秒版）

这三个框架都能写接口，区别在于它们已经替我们准备了什么。

`FastAPI` 比较适合以 API 为中心的项目。请求模型、数据校验和 OpenAPI 文档能围绕类型声明组织起来。如果要做完整后台和复杂权限，仍需要选择相应组件。

`Flask` 的核心比较轻，方便按项目拼装。代价是数据库、校验、权限等规则需要自己统一。它能支持 async 视图，但在传统 WSGI 部署下，这不等于每个 worker 可以同时服务多个请求。

`Django` 已经提供 ORM、认证和管理后台，适合确实需要这些能力的项目。它也有异步支持，但不能因此把所有中间件、数据库操作和事务都当成异步。

我会用同一个最小业务验证选型，看开发成本、部署方式和团队维护能力，不按“轻量等于小项目”来判断。

## 知识点详解：把功能清单和运行方式分开比较

### 先把一个项目拆成要交付的能力

假设我们要做一个课程后台。页面需要管理员登录，编辑课程，分配权限；移动端还要调用接口。这里不只有“返回 JSON”，还涉及用户模型、数据库迁移、管理页面和安全配置。

Django 已经提供不少这类能力，可以减少自己拼装的部分。FastAPI 能很好地组织接口，但完整后台未必是核心内置能力。Flask 也能完成，前提是我们愿意选择并维护相关扩展。

项目规模只是一个结果。更直接的比较是，这张功能清单里，框架完成了哪些，还有哪些要我们补。

![先看项目要交付什么](https://note.lgdsunday.club/img/Q550/02-capability-list.webp)

### FastAPI 的类型声明，承担了接口契约的一部分

假设接口接收课程标题、价格和讲师ID。FastAPI 配合数据模型，可以让这些输入经过类型与约束校验，同时生成相应API文档。

这能减少代码、文档和校验规则各写一套的问题。但类型声明不会证明讲师存在，也不会判断当前用户有编辑权限。这些仍需要业务代码。

所以不要把“自动校验”说成“自动处理业务”。框架校验字段，应用判断这些字段在当前业务中是否允许。

### Flask 留给我们更多选择，也留下更多约定要维护

使用 Flask，可以按需要接数据库、序列化、权限与任务队列。已有项目和团队规范已经围绕这些扩展建立时，继续使用可能更合适。

困难常出在大家各选各的。一个接口手写错误 JSON，另一个用扩展自动返回；一种认证放在装饰器里，另一种直接在业务中判断。框架小，项目规则却可能越堆越大。

因此，选择轻核心时，需要把错误格式、依赖管理、校验与测试规则定下来。否则省下的初始代码，会变成后续维护成本。

### async 要放进部署栈里看

FastAPI 通常按 ASGI 运行。一个请求等待可协作的异步 I/O 时，事件循环可以安排别的工作。但如果直接执行阻塞代码或 CPU 重计算，写了 async 也不会自动变轻。

Flask 的传统 WSGI 模式不同。async 视图可以在一个请求内并发等待多个外部操作，但请求仍占着一个 worker。官方文档也明确提醒，不要用这种方式随意启动需要跨请求存活的后台任务。

Django 可以采用 ASGI，也需要检查同步中间件、所调用库以及数据库操作。Django5.2中，事务尚不能直接按异步事务方式使用，需要把相关操作组织成同步函数，再通过合适方式调用。

这些差异应回到实际版本和部署配置确认，不能只比较函数前有没有 async。

![async 放在运行栈里才有意义](https://note.lgdsunday.club/img/Q550/03-async-stack.webp)

### 用一个小业务验证，胜过空谈谁性能最高

我会把登录、数据库写入、一个外部调用和错误处理做成同样的最小流程。先看团队能否把它写清楚，再看连接池、worker数量、等待时间和CPU利用率。

如果任务主要是 CPU 运算，换框架未必解决问题，可能需要进程或外部任务系统。如果瓶颈是数据库，框架排名也解释不了慢查询。

本文比较的是框架边界，没有给出三者性能实测结论。上线前还需要在相同业务和部署条件下测试。

## 面试官继续追问

### Django 可以只做 API 吗？

可以。是否使用额外API组件取决于校验、序列化和权限需求，不能把Django限定成只渲染页面的框架。

### FastAPI 能替我们完成认证吗？

它提供相关工具与文档支持，但身份来源、权限策略、会话或Token生命周期仍由应用设计。

## 面试速记卡

> - FastAPI：适合围绕类型与接口契约组织API。
> - Flask：核心轻，扩展选择和工程规范要自己统一。
> - Django：内置ORM、认证与后台等完整能力。
> - 异步：检查服务器协议、中间件、库和数据库，不只看async关键字。
> - 选型：用同一业务验证开发与维护成本，不编造性能排名。
