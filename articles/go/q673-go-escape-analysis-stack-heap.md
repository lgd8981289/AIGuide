# Go 逃逸分析是什么？变量什么时候分配到堆上？

下面是一段模拟面试对话。

🧑‍💻 **面试官：** Go 函数里创建一个变量，一定放栈上吗？

🙋‍♂️ **我：** 不一定，编译器会根据引用和生命周期做逃逸分析。

🧑‍💻 **面试官：** 那返回局部变量地址，在 Go 里合法吗？

🙋‍♂️ **我：** 合法，不能让返回的指针指向已经失效的存储。

🧑‍💻 **面试官：** 所以只要写了取地址或者 new，就一定有堆分配？

> 语法只告诉你创建了什么值；存储放在哪里，要看编译器能证明它被使用到什么时候。

## 面试速答（60 秒版）

逃逸分析是编译器对值的引用和生命周期所作的分析。能确认对象在当前相关执行范围内使用时，就有机会使用栈或直接优化掉分配；如果引用需要活得更久，就不能把它留在即将失效的栈空间。

因此，返回局部变量地址在 Go 里是合法的，编译器会安排有效存储。但取地址、使用 new 或转成接口，也不必然等于最终一定堆分配，还要看内联、调用位置和优化结果。

我会用指定版本编译器的 `-gcflags=-m=2` 查看分析，再用基准的分配统计和内存剖析确认实际成本。编译日志与运行时分配观测是两份证据，不能只凭一条语法规则预测全部情况。

优化时先找真实分配热点，不为了追求“零逃逸”牺牲代码结构，更不能用不安全指针破坏生命周期保证。

## 知识点详解：先问引用要活多久

### 返回一个值，和返回它的地址不同

假设函数创建局部整数 v，最后返回整数值。调用者拿到的是这个结果，不需要继续通过地址访问函数原来的局部存储。

如果返回 \&v，情况就变了。调用者在函数结束后仍可能使用它，编译器必须让对应存储继续有效。[Go FAQ 的堆栈说明](https://go.dev/doc/faq#stack_or_heap)强调，语言保证正确性，具体分配由实现决定。

这也说明，不应该拿 C 的悬空局部地址经验直接断言 Go 代码非法。但这不意味着两种语言的所有指针风险都能忽略，尤其 unsafe 不在普通保证的使用方式之内。

### 用小程序观察，而不是只看关键字

下面专门保留函数边界，减少内联让读者看不清来源的情况。它是 Go 编译器实验，不存在同一套 TS/Python 逃逸日志 API。

```go
package main

var kept *int
var result int

//go:noinline
func localValue() int {
    value := 7
    return value
}

//go:noinline
func escapedValue() *int {
    value := 9
    return &value
}

func main() {
    result = localValue()
    kept = escapedValue()
}
```

把它保存成 main.go，用当前目标编译器执行 `go build -gcflags=-m=2 main.go`。重点看 escapedValue 中 value 的流向和移动到堆的诊断，而不是把所有 “escapes” 单词都当成同一种业务问题。

这个例子把返回指针保存在包级变量中，使它的长期引用清楚。去掉函数边界、改变调用处或换版本，优化结果可能变化，所以测试记录必须保留编译器版本和完整代码。

![函数结束，返回指针仍要有效](https://note.lgdsunday.club/img/Q673/02-go-escape-analysis-stack-heap.webp)

### 为什么 new 和取地址不能直接决定位置？

new 表达创建某种类型的值并得到指针，但语言没有要求每次都必须通过堆分配器完成。编译器如果证明指针不离开可安全处理的范围，就可能采用其他安排。

内联还会让被调用函数和调用方一起分析。单看函数源码觉得“返回指针必逃逸”，到调用处可能发现这个对象根本不需要保留，甚至能被优化掉。

因此，逃逸分析是编译上下文里的结论，不是贴在某个关键字上的永久标签。

### 编译器诊断，还不是全部性能账单

先找 allocs/op 和分配字节，再用剖析确认大头在哪里。一个很少执行的小对象，即使进入堆，也未必值得重构；一个每次循环都创建的大 buffer，可能更值得检查。

也别忘了保留内存。为了减少分配而长期缓存巨大对象，可能增加堆占用和扫描成本。把对象放进 sync.Pool，也不是“从此不需要 GC”的保证。

## 面试官继续追问

### 堆分配一定慢到不能接受吗？

不一定。分配器、对象大小、分配频率和 GC 都影响成本。先测业务热点，比较改动前后的分配与延迟，不能把“逃逸”本身当作缺陷评级。

### 传值就完全没有共享了吗？

也不是。结构体中可能包含指针、切片或 map，传值会复制这些字段的值，背后的数据仍可能共享。复制语义、别名和存储位置要分别解释。

## 面试速记卡

> - 目的：证明引用和生命周期，安排不会失效的存储。
> - 返回地址：Go 中合法，编译器负责保证有效性。
> - 语法：new、取地址和接口转换不单独决定最终分配。
> - 证据：固定版本看编译诊断，再用分配统计与剖析核对。
> - 优化：先查热点，不为“零逃逸”滥用 unsafe 或长期保留大对象。
