# Dify 的 Chatflow 和 Workflow 有什么区别？多轮对话应该怎么选？

> 作者：程序员Sunday · [Sunday面试指南](https://note.lgdsunday.club/)
>
> [在线阅读与配图](https://note.lgdsunday.club/engineering/q511-dify-chatflow-vs-workflow/) · [题库目录](../../README.md)

下面是一段模拟面试对话。

🧑‍💻 面试官：Dify 的 Workflow 和 Chatflow 怎么选？

🙋‍♂️ 我：Workflow 用来执行流程，Chatflow 用来聊天。

🧑‍💻 面试官：Workflow 里也能调用大模型生成文字。如果用户接着说“把刚才的报告改成英文”，需要增加什么？

🙋‍♂️ 我：需要把上一轮报告带进新一轮。

🧑‍💻 面试官：把历史都存下来就够了吗？用户先说中文，下一轮改成英文，流程到底用哪个条件？

> 区别要落到「一轮执行」和「跨轮会话」：有聊天入口以后，仍然要设计哪些信息保存、哪些信息更新、哪些信息进入本轮模型。

## 面试速答（60 秒版）

Dify 的 Workflow 和 Chatflow 都能用节点连接模型、检索、工具与条件分支。主要区别是应用怎样接收任务，以及是否提供持续的会话层。

Workflow 根据一次输入运行流程，处理以后返回结果。例如上传材料，生成一份报告。

Chatflow 则面向多轮对话。用户每发送一条消息，就会触发一次设计好的流程，应用可以结合会话历史和会话变量处理追问。[Dify 官方比较](https://docs.dify.ai/en/cloud/use-dify/build/workflow-chatflow)。

因此，一次提交就能明确完成的任务，可以选 Workflow；用户需要补条件、修改要求或持续追问时，Chatflow 更符合交互方式。

不过，多轮对话不代表模型自动理解了所有历史。咱们还需要安排本轮如何读取历史、更新条件，并避免上一轮的信息错误覆盖新要求。

## 知识点详解：同一个报告功能怎样变成多轮对话

### Workflow 解决一次输入怎样变成结果

假设用户上传一份材料，选择输出语言，再点击“生成报告”。

流程可以先解析材料，再检索补充内容，然后让大模型生成报告，最后返回结果。中间同样可以包含分支、循环和错误处理。

这种使用方式的重点是：这次运行所需要的输入，是否已经准备好。它不是因为节点少才叫 Workflow，也不要求全程不使用模型。

后面用户想重新生成，可以再提交一次输入。如果应用自己实现会话存储，也能把历史传入 Workflow，但这部分交互与状态管理需要另外安排。

### Chatflow 在每轮执行外面增加会话

现在把按钮改成聊天输入。用户先说：“用中文整理这份材料。”下一轮又说：“换成英文，保留刚才的结构。”

此时，第二条消息需要关联前一轮材料和报告，而不是只对“换成英文”这几个字作回答。

Chatflow 提供面向会话的应用形态，但每条消息仍然会触发一次流程。它不是第一轮启动以后，所有节点永远停在那里等待用户。[两类流程的交互方式](https://docs.dify.ai/en/cloud/use-dify/build/workflow-chatflow)。

可以把它理解成：会话保留一部分跨轮信息，每轮拿到新消息以后，再把相关信息交给节点处理。

![多轮对话不是一条流程一直走](https://note.lgdsunday.club/img/Q511/02-conversation-rounds.webp)

### 临时结果、会话条件与模型历史需要分开

咱们可以给报告助手设计三个不同的对象：

- 当前运行的解析结果：服务于这一次流程执行。
- 会话里的报告要求：例如语言、资料标识和最近确认的结构。
- 交给 LLM 节点的消息历史：帮助模型理解“刚才”“保持原样”等说法。

它们有联系，但用途不同。保存了会话变量，不代表所有节点自动引用它；保存了完整聊天，也不代表每次模型调用都要加载全部历史。

假设用户明确把语言改成英文，那么流程应把有效条件更新为英文，再生成报告。不能在提示词里同时塞入“用中文”和“用英文”，却不告诉模型哪个是当前要求。

可以让参数提取节点识别本轮修改，再根据有无明确新值更新条件。这里是应用的设计方法，具体节点与变量写法要按部署版本核对。

![临时结果、会话条件、模型历史](https://note.lgdsunday.club/img/Q511/03-state-scope.webp)

### 选择节点时，也要注意入口和输出

当前官方文档区分了两类应用可用的启动和输出方式，例如 Workflow 的 User Input／Trigger 与 Chatflow 的会话输入，以及 Output／Answer 的用途。

Answer 面向对话中的回复，Output 面向流程结果。名字相似时，应该检查这个节点负责显示什么、在哪种应用中使用，不要把旧版本的 End 节点教程直接套进当前界面。

需要结构化批处理、定时触发的任务，优先按 Workflow 的运行形态设计；用户逐轮沟通的任务，再使用 Chatflow 的会话能力。模型是否自主选择工具，是另一道控制权问题。

## 面试官继续追问

### 为什么第二轮有历史，仍然回答错了？

先看 LLM 节点实际拿到的输入。可能上一轮报告没有被引用，可能资料版本已变化，也可能旧条件与新条件没有区分。

排查时对照“会话保存了什么”和“这一轮送进去什么”，比一直修改系统提示词更直接。

### 两个用户都在生成报告，会串会话吗？

正确使用会话身份和存储范围时应隔离。自定义工具、外部缓存和共享文件仍要分别检查。

例如工具不能只按“最近一次报告”读取全局文件，而应按可信用户和当前任务定位资料。

### 怎样测试多轮流程？

至少准备四类对话：连续追加要求、明确覆盖旧条件、另开会话，以及上一轮处理失败后的追问。检查实际条件、模型输入和最终结果，不只看流程是否执行成功。

## 面试速记卡

> - Workflow：一次输入触发流程，处理后返回结果。
> - Chatflow：每条消息触发流程，外层有持续的会话。
> - 共同点：都能组合模型、工具、检索和条件分支。
> - 多轮重点：保存历史、更新条件和实际引用是不同动作。
> - 排查入口：核对本轮 LLM 输入，确认有效条件有没有进入模型。
