# JavaScript sort 为什么可能排错数字？比较器、稳定性和 toSorted 有什么区别？

*以下对话为教学模拟，用来讲解这道题。*

🧑‍💻 面试官：给 `[2, 10, 3]` 排序，你会怎么写？

🙋‍♂️ 我：调用 sort，默认就是升序。

🧑‍💻 面试官：结果却是 `[10, 2, 3]`。那比较器写成 `(a, b) => a > b` 行不行？

🙋‍♂️ 我：它能判断大小，应该可以吧。

🧑‍💻 面试官：但它只返回 0 和 1。再问一步，拿状态里的数组直接 sort，会不会把原数据一起改掉？

> 这道题要分清三件事：比较规则是什么，相等项怎样排列，以及排序有没有改动原数组。

## 面试速答（60 秒版）

JavaScript 的 sort 默认按字符串的 UTF-16 码元顺序比较，并不会因为数组里装着数字，就自动按数值大小排序。因此，普通有限数字的升序排序需要提供 `(a, b) => a - b`。

比较器返回负数，表示 a 排在 b 前面；返回正数，表示 a 排在后面；返回 0，表示两者在本次排序规则下相等。只返回布尔值，表达不完整，不能保证结果正确。

sort 会修改原数组，而且返回的也是这个数组。toSorted 则建立一个排好序的新数组，适合需要保留原顺序的情况，但它只是浅拷贝，里面的对象仍可能共享。

现代 ECMAScript 要求排序稳定，也就是比较结果相等的元素，保留原来的先后顺序。不过，稳定不代表比较器写错以后，运行时还会帮我们修好。

## 知识点详解：同样叫排序，先确认它按什么比较

### 10 为什么跑到了 2 前面？

咱们假设一个商品列表的价格是 2、10、3。调用 `sort()` 以后，默认比较过程中使用的是字符串 `"2"`、`"10"`、`"3"`。

比较到第一位，`"1"` 就排在 `"2"` 前面，所以 10 会先出来。数组元素本身仍然是数字，只是默认比较规则用到了它们的字符串表示。

因此，先不要怀疑数字变成了字符串。真正需要修改的是比较规则。

#### TypeScript

```ts
const prices = [2, 10, 3];
const ordered = prices.toSorted((a, b) => a - b);
console.log(ordered); // [2, 3, 10]
console.log(prices);  // [2, 10, 3]
```

#### Python

```python
prices = [2, 10, 3]
ordered = sorted(prices)
print(ordered)  # [2, 3, 10]
print(prices)   # [2, 10, 3]
```

这里的 Python 对照只说明“保留原数组，得到数值顺序”。Python 对数字的默认排序不会先转字符串，`sorted` 常用 key 函数提取比较键，也不是照搬 JavaScript 的二元比较器。

### 比较器需要把反方向也说清楚

如果 a 大于 b，那么 `a - b` 返回正数；把参数交换以后，就返回负数。两次比较表达的是同一套顺序。

但 `a > b` 只会返回 true 或 false，转成数字就是 1 或 0。比如比较 10 和 2 返回 1，交换参数比较 2 和 10 却返回 0。前一次说“10 应该在后面”，后一次又说“它们相等”。排序算法拿到的是一套互相矛盾的规则。

比较器还应该保持确定、满足传递关系，不要在里面随机返回结果，或者一边比较一边修改参与排序的数据。规范没有规定引擎必须按哪种顺序、调用多少次比较器，也没有承诺所有引擎使用相同的排序算法。

`a - b` 还有使用条件。如果数据可能包含 NaN，就应该先规定 NaN 放在哪里。不能把“返回 NaN 时按相等处理”误认为“NaN 已经排好了”。

![布尔返回值缺失一个方向造成比较不一致](https://note.lgdsunday.club/img/Q741/02-comparator-signs.webp)

### 稳定排序保留的是什么？

假设有三条记录，原顺序为 A 组 2 分、B 组 1 分、C 组 2 分。只按分数升序排序，得到 B、A、C。A 和 C 比较结果都是 0，因此保留原来的 A 在 C 前面。

这就是稳定性。它不会自动增加“同分按名字排序”的规则。如果需要这个规则，要在比较器里继续比较名字。

[ECMAScript 排序规范](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.sort)要求稳定排序，但不要求所有引擎采用同一种算法。因此，面试时可以回答稳定性，却不要把“底层永远是快速排序”当成语言保证。

### 新数组也可能仍然改到旧对象

`sort` 会原地排列。另一个变量如果引用同一个数组，也会看到顺序变化。toSorted 则不会重排原数组，这对 React 状态更新、保留原始搜索结果等场景很重要。

不过，新数组里的商品对象还是那些对象。修改 `ordered[0].price`，仍可能影响原列表中同一个商品的 price。

所以，要分开“数组顺序是否独立”和“元素对象是否独立”。toSorted 解决前一个问题，不负责深拷贝。旧环境没有 toSorted 时，可以先复制再 sort，并通过目标运行环境的兼容性检查确认支持情况。

![toSorted只复制数组容器不复制元素对象](https://note.lgdsunday.club/img/Q741/03-shallow-copy-identity.webp)

## 面试官继续追问

### 字符串里的中文名字应该怎样排序？

默认 UTF-16 顺序通常不是产品想要的语言排序。可以根据语言和规则使用 `Intl.Collator`，再把 compare 交给排序；同时明确大小写、数字片段、地区规则，不把任何一种顺序称为唯一正确的中文排序。

### Python 的 list.sort 也返回数组吗？

不会。Python 的 list.sort 原地修改并返回 None；JavaScript 的 sort 原地修改并返回原数组。两者都原地，不代表返回值约定相同，更多差异见 Q571。

### 怎样检查排序代码没有偷偷改数据？

至少检查数值顺序、重复项的相对顺序、原数组顺序和对象身份。业务允许 NaN、空值或缺字段时，再单独补比较规则与用例。只拿 `[1, 2, 3]` 测试，默认排序和错误比较器都可能侥幸通过。

## 面试速记卡

> - 默认规则：按字符串的 UTF-16 码元顺序，不是自动按数值排序。
> - 比较器：负数在前，正数在后，0 表示本规则下相等。
> - 稳定排序：相等项保留原来的相对顺序。
> - sort：修改并返回原数组；toSorted：返回排序后的浅拷贝。
> - 验证重点：数字、相等项、原数组、共享对象和特殊值。
