# React 自定义 Hook 是什么？多个组件调用同一个 Hook，会共享状态吗？

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：两个组件调用同一个 useCounter，会共享计数吗？

🙋‍♂️ 我：一般不会，自定义 Hook 复用的是逻辑，各自有自己的状态。

🧑‍💻 面试官：如果 Hook 里面读的是模块顶层的对象呢？

🙋‍♂️ 我：那两个调用可能读到同一个外部对象，不能只看函数名字判断隔离。

🧑‍💻 面试官：如果现在确实要共享，你会把状态放在哪里？

> 先找状态真正保存在哪里，再判断共享；复用同一个 Hook 函数不代表复用同一份状态。

## 面试速答（60 秒版）

自定义 Hook 是一个可以调用其他 Hook 的函数，用来复用组件中的状态逻辑。例如把计数、订阅或表单处理整理成 useXxx。

两个组件调用同一个自定义 Hook 时，内部 useState 仍分别属于各自组件的那次调用。因此，一个计数器更新，不会自动修改另一个计数器。

不过，如果 Hook 订阅同一个外部 Store，或者访问模块作用域里的可变对象，就可能共享这些外部数据。真正需要共享时，可以提升状态或使用合适的外部状态方案；不要靠函数写在同一个文件里就猜它共享或隔离。

## 知识点详解：同一个函数，为什么能产生两份状态

### 函数代码只有一份，状态可以有两份

假设页面左侧和右侧各有一个计数器，两个组件都调用 useCounter。

useCounter 里如果使用 useState，React 会把这份状态记录在相应组件的 Hook 调用位置。左组件更新时，修改的是左组件那份状态。函数代码可以相同，但记录没有变成一份全局数据。

同一个组件连续调用两次自定义 Hook，也需要分别理解各自调用位置。不能把函数名字当作状态的唯一标识。

### 自定义 Hook 把可重复的过程放在一起

比如多个组件都需要订阅网络状态。可以把状态初始化、订阅以及卸载清理写进自定义 Hook，让组件直接使用结果。

这样复用的是‘怎样取得并维护这个值’。组件依然需要遵守 Hook 调用规则，函数提取以后，条件调用不会自动合法。

设计时让参数与返回值表达真实职责。一个 Hook 如果顺便操作多个无关模块，虽然少写了几行代码，也可能让组件更难理解。

![状态记录在调用位置](https://note.lgdsunday.club/img/Q541/02-call-slots.webp)

### 共享来自外部存储，不是 use 前缀

假设 Hook 读取模块顶层的 settings 对象。这个对象在模块实例中只有一份，两个组件都可能访问它。

不过，修改普通对象也不代表 React 自动知道应该重渲染。若共享数据由外部 Store 管理，就需要正确的订阅与快照协议，不能用一次读取代替同步。

因此，‘每次调用内部状态独立’与‘Hook 可以读取共享数据’可以同时成立。先画出值保存在哪里，再看是谁订阅、谁更新。

![共用的是外部 Store](https://note.lgdsunday.club/img/Q541/03-external-store.webp)

### 真要共享，给状态找一个清楚的归属

两个计数器需要同步时，可以把状态提升到共同父组件，再把值和更新方法传下去。跨较大范围的共享，则评估 Context 或外部 Store。

这道题不需要把状态库全部比较一遍。重要的是让所有使用方知道谁保存值、谁有权更新、什么时候通知。

检查 Hook 时，用两个组件分别更新，再卸载其中一个，确认剩余组件的订阅没有被误清理。参数改变时也要检查旧订阅是否结束。

依据：[React 自定义 Hook](https://react.dev/learn/reusing-logic-with-custom-hooks)。

## 面试官继续追问

### 一个组件调用两次 useCounter，也是独立的吗？

内部使用常规状态 Hook 时，各次调用有各自位置。若两次都读取同一外部对象，外部数据仍可能共享。

### 把变量写在 Hook 外面，就能当全局状态吗？

能共享一个模块值，但还要解决更新通知、并发、生命周期和服务端范围等问题，不能只移动变量位置。

### 两个实例共用一个订阅，应该怎样清理？

需要按订阅实现管理引用与退订，避免一个实例卸载就终止所有人的连接。若每个实例独立订阅，则各自清理自己的资源。

## 面试速记卡

> - 自定义 Hook：复用有状态逻辑。
> - 内部状态：属于组件的相应调用位置。
> - 外部数据：可能由多个调用共享。
> - 共享方案：明确保存、更新与订阅职责。
> - 卸载：清理自己拥有的资源。
