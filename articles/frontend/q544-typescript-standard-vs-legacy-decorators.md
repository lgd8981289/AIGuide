# TypeScript 装饰器是什么？标准装饰器和 experimentalDecorators 有什么区别？

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：TypeScript 装饰器是怎样工作的？

🙋‍♂️ 我：可以在类或成员定义时增加注册或包装逻辑，不用修改调用方写法。

🧑‍💻 面试官：experimentalDecorators 打开和不打开，装饰器函数参数都相同吗？

🙋‍♂️ 我：不同，旧写法和新提案写法有不同的签名。

🧑‍💻 面试官：如果依赖参数装饰器和 emitDecoratorMetadata，能直接切换吗？

> 看到 @ 语法以后，先确认编译采用哪套语义，再解释装饰时机、参数与兼容性。

## 面试速答（60 秒版）

TypeScript 装饰器可以在类或成员定义过程中执行逻辑，例如注册、替换方法或安排初始化。它执行的时机，和方法以后被调用的时机，需要分别理解。

TypeScript 5.0 支持的新装饰器提案写法，通常接收被装饰的值和 context；启用 experimentalDecorators 的旧写法则采用另一套参数与处理规则。

两者不能只改一个开关就认定兼容。新提案路径不等同旧的 emitDecoratorMetadata，也不支持旧式参数装饰器。升级时应检查框架依赖、装饰目标和编译结果，不能把 Python 的装饰器规则直接套过来。

## 知识点详解：同一个 @，为什么可能采用两套调用规则

### 装饰时执行，和包装方法被调用不同

假设给一个方法增加调用日志。装饰器可以在类定义处理中取得原方法，创建包装方法并把它交回。以后用户调用这个方法，才会进入包装逻辑。

如果装饰器只做注册，它的主要工作可能就在定义阶段完成，并不一定每次调用都重新注册。

因此，读代码时先问这一行属于装饰应用、实例初始化，还是实际方法调用。不能把装饰器函数的所有语句都当成‘每次调用前执行’。

![装饰应用和方法调用是两步](https://note.lgdsunday.club/img/Q544/02-timing.webp)

### 新版 value/context 和旧版参数，要分开讲

以方法为例，新提案写法可拿到原方法值与描述目标的 context。context 提供目标种类、名字及相应能力，装饰器按允许的返回规则处理。

legacy 方法装饰器常见的是 target、成员名称和属性描述符。不同装饰目标的参数也不完全相同。

| 检查项                     | 新提案支持路径      | legacy 路径             |
| ----------------------- | ------------ | --------------------- |
| 方法参数约定                  | 方法值与 context | target、成员名、descriptor |
| 参数装饰器                   | 不按旧方案支持      | 可有旧式参数装饰器             |
| 旧 emitDecoratorMetadata | 不直接兼容        | 相关旧元数据方案              |

这张表是版本边界，不代表所有新旧装饰器都不能写适配。实际库是否兼容，应检查它支持哪一套输入。

### 多个装饰器，顺序要跟着实际包装看

如果一个装饰器做日志，另一个做缓存，组合后到底是命中缓存时还记录日志，还是直接跳过日志，要看求值、应用和返回包装的关系。

可以画出最终调用链，再用少量输入检查。不要只背‘从上往下’或‘从下往上’，把表达式求值顺序与装饰器应用混成同一个阶段。

初始化相关能力还有独立时机。需要依赖成员或 this 的装饰器，应回所用版本的规则核对，而不是按照一个方法包装例子概括全部对象。

![先看最终包装顺序](https://note.lgdsunday.club/img/Q544/03-wrapping.webp)

### 旧框架迁移，重点检查它依赖什么

假设框架通过参数装饰器和旧元数据识别依赖。切换到新提案支持路径时，编译能否接受、元数据是否存在、容器能否正确创建对象，都需要验证。

TypeScript 装饰器并不自动提供完整运行时类型校验，也不意味着所有环境都能直接执行未编译语法。具体构建链同样需要支持。

本篇没有提供一个 Python 同名 API。Python 函数装饰器是另一套语言机制，若用它模拟元数据和参数规则，反而会讲错。

依据：[TypeScript 5.0 官方说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html)。

## 面试官继续追问

### 不写 experimentalDecorators 就一定能运行吗？

还要检查 TypeScript 版本、编译目标与构建链。新语义支持和运行时直接执行，是不同条件。

### 装饰器返回的函数必须保留 this 吗？

需要按原方法调用约定保留必要的 this、参数、返回值和异常行为。否则包装会改变调用语义。

### emitDecoratorMetadata 能提供完整类型系统吗？

不能把旧元数据当成完整的 TypeScript 类型信息，泛型、联合等不能据此自动得到完整业务校验。

## 面试速记卡

> - 先确认使用新提案还是 legacy 语义。
> - 定义、初始化、调用分别检查时机。
> - 新方法装饰器：value 与 context。
> - 参数装饰器与旧元数据：不能直接迁移。
> - 升级：检查框架、构建链和实际结果。
