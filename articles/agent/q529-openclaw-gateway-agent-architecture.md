# OpenClaw 是什么？Gateway、Agent 和工具之间是怎样协作的？

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：OpenClaw 的核心原理是什么？

🙋‍♂️ 我：它把聊天渠道、大模型和工具接起来，让用户从聊天窗口交代任务。

🧑‍💻 面试官：那么两个人同时发来消息，聊天历史怎么区分？模型又是直接操作本地文件吗？

🙋‍♂️ 我：需要先把消息归入对应会话，文件操作由工具执行。

🧑‍💻 面试官：如果聊天渠道断开，但文件已经改了，你会沿哪条链查？

> 答好 OpenClaw，要能沿着一条消息分清‘谁接入、谁决定、谁执行、谁把结果送回去’。

## 面试速答（60 秒版）

`OpenClaw` 是一套可以接入多个聊天渠道、运行 Agent 并调用工具的助手系统。用户看到的是聊天窗口，背后还需要 Gateway、会话和运行环境配合。

`Gateway` 是长驻的接入与协调中心。它管理渠道连接，并把消息交给配置指定的 Agent 与会话。Agent 运行时整理当前输入、调用模型，并处理模型提出的工具请求；模型负责判断下一步，真正的文件、命令或设备操作由具体工具完成。

因此，排查问题时要沿着消息链看。消息没进来，检查渠道和 Gateway；消息进来了却没完成任务，再检查运行记录、模型响应和工具结果。工具权限、设备连接和发送是否成功，也都需要单独确认。

![一条消息怎样完成任务](https://note.lgdsunday.club/img/Q529/01-overview.webp)

## 知识点详解：一条聊天消息怎样变成一次工具操作

### 先从用户看到的聊天窗口往里走

假设用户在聊天软件里说，‘帮我整理今天的会议记录’。

聊天软件只负责把这句话送进来。Gateway 接住渠道消息以后，还要知道它来自谁、属于哪个会话，以及应当交给哪个 Agent。否则两个用户同时请求，模型就可能拿到不属于自己的历史。

Gateway 也为控制客户端和节点提供连接入口。管理界面、CLI 和设备节点可以通过协议与它交互，但这些连接的职责并不相同。不能把所有连接都看成一次普通聊天请求。

![两个人的消息，进入不同会话](https://note.lgdsunday.club/img/Q529/02-session.webp)

### Agent、模型和工具，各自完成哪一步

运行时拿到任务以后，先整理本轮模型需要看到的内容，例如用户问题、相关历史和可用工具。

模型可能判断需要读取会议文件，于是提出一个工具请求。接下来，运行环境检查允许的操作，再调用实际工具。工具返回文件内容以后，运行时把结果带回模型，模型才能继续整理摘要。

所以，‘模型决定读哪个文件’和‘程序真正读取文件’是两个动作。能生成正确的工具名称，不代表文件一定存在，也不代表进程拥有读取权限。具体运行时还可能来自不同的配置，不能只凭产品名称推断底层实现。

![提出工具请求，和执行工具分开](https://note.lgdsunday.club/img/Q529/03-tool-boundary.webp)

### 会话连续性和运行恢复，要分别检查

会话用来组织一段对话。一次具体执行则可能包含若干模型调用和工具操作。

假设摘要已经写入文件，发回聊天窗口时却断线了。如果直接重新执行整个任务，可能再写一次文件。排查时应先找出已经完成的动作，再判断只重发结果，还是继续未完成步骤。

保存聊天历史也不自动保证所有副作用都能恢复。持久化范围、工具幂等和运行状态，要按实际后端及配置验证。

![文件已完成，消息还没送达](https://note.lgdsunday.club/img/Q529/04-recovery.webp)

### 工具能访问哪里，权限就要管到哪里

如果工具在宿主机执行，宿主机上的文件和凭据就可能成为它的能力范围。若通过沙箱或设备节点执行，则还需要确认挂载、命令和节点能力的边界。

咱们可以先给文件整理任务只读权限，再测试它能否读到授权目录之外的文件。涉及覆盖、删除或发消息的动作，则检查审批和审计记录。

验证功能时也要拆开看。一次任务应该能对应到接入消息、运行过程、工具结果和返回消息，而不只是最后一段听起来正确的摘要。

依据：[OpenClaw 官方架构文档](https://docs.openclaw.ai/concepts/architecture)。

## 面试官继续追问

### Gateway 是不是大模型？

不是。它负责连接和协调等系统工作，模型推理由配置的模型服务或运行能力承担。模型故障和 Gateway 故障应分别定位。

### 接上聊天渠道，就能让多人安全共用吗？

还需要确认会话路由、用户身份、工具授权和数据隔离。接入成功只能说明消息能到达，不能证明所有边界都设置正确。

### 把 OpenClaw 放进容器就安全了吗？

要继续看工具在哪里执行、挂载了什么、是否共享凭据以及节点权限。容器只是部署条件的一部分。

## 面试速记卡

> - Gateway：接入渠道并协调连接与路由。
> - 会话：组织用户当前这段对话。
> - 运行时：组织模型与工具之间的执行过程。
> - 模型做判断，工具完成实际操作。
> - 故障定位：接入、执行、副作用和发送分别查。
