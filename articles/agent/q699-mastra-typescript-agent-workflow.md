# Mastra 是什么？Agent 和 Workflow 如何接入 TypeScript 项目？

>
> [在线阅读与配图](https://note.lgdsunday.club/agent/q699-mastra-typescript-agent-workflow/) · [题库目录](../../README.md)

*下面是一段模拟面试对话。*

🧑‍💻 面试官：前端团队已经使用 TypeScript，接入 Mastra 后，是不是可以直接在页面里运行所有 Agent 工具？

🙋‍♂️ 我：语言相同不代表执行位置相同。访问数据库、使用模型密钥和修改业务数据的工具，仍然应该在可信服务端执行。

🧑‍💻 面试官：那 Mastra 的 Agent 和 Workflow，分别放在哪里？

🙋‍♂️ 我：它们可以作为应用后端的能力。Agent 处理开放判断，Workflow 规定需要固定安排的步骤。

🧑‍💻 面试官：流程等待用户审批时，页面关了，下一次怎样接着执行，而不是再启动一遍？

> TypeScript 统一的是开发语言；运行位置、流程控制和任务恢复，仍然需要分别设计。

## 面试速答（60 秒版）

Mastra 是面向 TypeScript 的 AI 应用框架，可以组织 Agent、工具、Workflow、存储和运行观测等能力，并接入已有的应用。

Agent 根据目标和当前信息选择工具；Workflow 则由开发者定义步骤、数据约定和执行路径。两者可以组合，比如外层流程检查资料、等待审批，再让局部 Agent 完成需要动态判断的任务。

对已经使用 TypeScript 的团队来说，类型、工具函数和服务代码更容易放进同一套工程。但这不代表模型密钥和高权限工具可以直接交给浏览器。

如果任务还需要暂停与恢复，就要配置相应存储，保存运行身份和状态，并在恢复时重新校验操作者及审批内容。框架提供恢复机制，业务动作的幂等和当前权限仍然由应用负责。

## 知识点详解：同一种语言，可以承担不同的运行职责

### Mastra 接进来以后，应用多了哪些对象？

假设咱们正在做一个报告助手。用户在页面上提交资料，后端查询数据，生成报告，最后让用户确认是否发送。

在 Mastra 中，可以把查询数据封装成工具，把负责分析资料的执行角色定义为 Agent，再把“准备资料、生成、审批、发送”的整体过程组织为 Workflow。[官方概览](https://mastra.ai/docs)介绍了这些能力如何作为框架组件使用。

页面只需要调用后端入口，展示结果与进度。数据库连接、供应商密钥和发送权限留在可信服务端。浏览器能够调用接口，不等于浏览器已经取得了底层工具的全部权限。

### Agent 与 Workflow 的区别，落在谁安排下一步

用户只说“找出报告中最值得解释的异常”，下一次查哪个指标，可能取决于上一次结果。这类局部判断适合交给 Agent。

而发送前必须确认收件人、必须通过审批，就应该明确写进外层流程。不能仅靠一句提示词，让模型自觉等用户同意。

Mastra 的[工作流说明](https://mastra.ai/docs/workflows/overview)通过步骤的输入输出 Schema 和连接方式组织流程。步骤中可以调用 Agent，也可以直接运行普通函数。引入 Workflow，并不表示每一步都得再调用一次模型。

![固定步骤里，留一段给模型判断](https://note.lgdsunday.club/img/Q699/02-mastra-workflow-agent.webp)

### 暂停与恢复，需要找回同一次运行

报告生成以后，如果等待审批，系统应该记录当前运行、待审批内容和审批状态。恢复时带回的是这一次运行的输入，而不是把“用户同意了”当成一句新的普通聊天再开始任务。

还要把运行身份和授权分开。知道 `runId`，只能帮助系统定位任务；服务端仍需要检查这个用户能不能审批，以及他看到的是否仍是同一版报告。

对应的[暂停与恢复说明](https://mastra.ai/docs/workflows/suspend-and-resume)需要结合实际存储配置阅读。内存里有对象，不代表服务重启后也能找回来。即使找回流程状态，发送邮件或写数据库的结果也要用业务记录核对。

![恢复的是同一次运行，不是再建一遍](https://note.lgdsunday.club/img/Q699/03-mastra-resume-run.webp)

### 框架接入成功，怎样验收？

先固定一份小数据，检查工具收到的参数、生成内容引用的数据、等待审批的位置，以及恢复后有没有重复发送。然后增加工具超时、用户关闭页面、服务重启和审批内容已变更几种情况。

Agent 相关结果可以包含文本、工具调用、步骤和使用量等信息，具体以所用版本的[Agent 接口文档](https://mastra.ai/docs/agents/overview)为准。不要只把最终文本打印出来，就丢掉导致失败的中间信息。

选型也要看团队能否维护这些运行组件。一次简单模型调用未必需要整套框架；需要多轮工具、流程编排与持续运行时，再比较框架能减少哪些维护工作。

本文核对框架职责与恢复条件，没有部署 Mastra、调用真实模型或模拟生产故障。它的原生生态是 TypeScript，不提供伪装成同库实现的 Python 代码。

## 面试官继续追问

### 采用 Next.js，就能把工具都写成客户端函数吗？

不能。项目框架和执行权限是两回事。涉及密钥与受保护资源的工具应在服务端运行，接口还要完成登录、授权和参数检查，不能把模型生成的身份当可信信息。

### Workflow 有暂停能力，还需要业务状态表吗？

需要看业务事实由谁管理。流程状态表示执行到哪里，业务状态表可以表示邮件是否已经发送、某次审批针对哪个版本。两者可以关联，但不能互相凭空替代。

### 怎样避免为了接框架而重写全部后端？

先把现有服务封装成清晰的工具，只迁移一条完整任务。保持原有鉴权、事务和业务接口，再评估哪些运行工作交给框架更合适。

## 面试速记卡

> - Mastra 面向 TypeScript AI 应用，语言相同不等于运行位置相同。
> - Agent 决定局部动作，Workflow 规定需要明确控制的执行路径。
> - 高权限工具与供应商密钥留在可信服务端。
> - 暂停恢复依赖运行身份、存储和恢复输入，不靠重新开始一轮聊天。
> - runId 不是权限凭证，恢复后仍检查版本、授权与业务幂等。
