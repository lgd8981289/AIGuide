# ReWOO 和 ReAct 有什么区别？Agent 为什么可以先规划，再调用工具？

> 作者：程序员Sunday · [Sunday面试指南](https://note.lgdsunday.club/)
>
> [在线阅读与配图](https://note.lgdsunday.club/agent/q534-rewoo-vs-react/) · [题库目录](../../README.md)

*下面是模拟面试对话，用来讲解本题，不是真实面经。*

🧑‍💻 面试官：ReWOO 和 ReAct 的区别是什么？

🙋‍♂️ 我：ReAct 每次拿到观察再决定下一步，ReWOO 把部分规划提前做完。

🧑‍💻 面试官：如果第二个查询需要第一个查询得到的机构名，提前规划是不是没法写？

🙋‍♂️ 我：可以先使用变量占位，执行以后再把结果填进去。

🧑‍💻 面试官：那如果第一个查询返回了三家机构，原计划还能直接往下走吗？

> ReWOO 先表达动作之间的依赖，执行时再填入证据；输入形态变了，预先计划也需要处理。

## 面试速答（60 秒版）

`ReAct` 常把推理、行动和观察交替进行。模型拿到工具结果以后，再判断下一步。

`ReWOO` 则把规划、工具执行和答案整理分开。Planner 先生成一组操作和证据变量，Worker 按依赖执行并填入实际结果，Solver 再根据这些证据组织答案。

因此，即使后一步依赖前一步，Planner 也可以先用变量表达关系，不必每调用一次工具都重新写完整计划。它适合依赖较清楚的任务，但工具返回和计划预期不符时仍要处理，不能认为提前规划就能省掉失败检查或动态调整。

## 知识点详解：计划中暂时不知道的值，怎样在执行时补进去

### ReAct 为什么要反复读取观察

假设任务要查某位作者所属机构，再查机构所在城市。

ReAct 可以先请求作者信息，拿到机构名以后，决定继续查询城市。如果第一步发现同名作者，也可以先澄清再往下走。下一步受到当前观察影响，是这种循环的特点。

好处是能及时调整；代价是模型在多轮中持续读取已有材料并判断。具体开销要看任务、上下文和实现，不能简单说每轮都浪费。

### ReWOO 先把依赖写出来

Planner 不需要提前知道机构名的真实内容。它可以表达这样的计划，第一步查作者所属机构，把结果保存在 E1；第二步查 E1 中机构的位置，把结果保存在 E2。

E1 和 E2 在这里代表待获得的证据，不能把它们当成模型已经查到的事实。

Worker 真正执行第一步以后，再把实际结果填入后面的调用。于是计划可以预先列出来，数据仍然在运行时才出现。这里也不是完全没有观察，而是规划推理与工具观察的安排不同。

![占位变量，在执行时变成证据](https://note.lgdsunday.club/img/Q534/02-variables.webp)

### Worker 完成依赖，Solver 整理证据

Worker 需要按引用关系安排执行。第二步引用 E1，就必须等 E1 的有效结果可用，不能把两步无条件同时发出去。

得到 E1、E2 后，Solver 结合原问题和证据生成答案。它应该知道结果来自哪个工具，以及哪些内容仍不确定。

如果 Worker 收到的是超时或空结果，不能把这类状态直接塞进机构名。一个可用的工程实现需要识别失败并交回可处理的信息。论文的分工不会替应用解决所有异常。

![后一步等待前一步的有效结果](https://note.lgdsunday.club/img/Q534/03-dependency.webp)

### 返回结果变了，计划就可能需要重做

假设第一步返回三位同名作者，各自属于不同机构。原来‘拿一个机构去查城市’的计划已经缺少选择条件。

这时可以向用户澄清，也可以按任务允许的范围扩展查询，再重新规划。具体怎样调整由实现决定，不应把这些额外机制都当作 ReWOO 自动提供。

比较方案时，既要检查最终答案，也要记录模型调用、工具调用、输入长度和失败恢复。提前规划可能减少反复推理，也可能提前写出后面根本不需要的步骤。

依据：[ReWOO 原论文](https://arxiv.org/abs/2305.18323)。

## 面试官继续追问

### ReWOO 的所有工具能并行吗？

只有相互独立且资源、权限允许的调用才可以并行。引用前一步证据的操作需要等待结果。

### Planner 写出 E1，就算知道查询答案了吗？

没有。它只是指定结果位置。真实证据必须来自执行结果，并检查有效性。

### 任务经常改变方向，还适合 ReWOO 吗？

要评估重规划频度与成本。路径高度依赖新观察时，交替决策可能更直接，也可以只对依赖清楚的子任务提前规划。

## 面试速记卡

> - ReAct：行动之后用观察继续判断。
> - ReWOO：规划、执行、整理分开。
> - 证据变量：先表达依赖，后填真实值。
> - 有依赖的动作不能无条件并行。
> - 工具返回变化时，检查、澄清或调整计划。
