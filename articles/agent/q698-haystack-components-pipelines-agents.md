# Haystack 是什么？Component、Pipeline 和 Agent 怎样配合？

> 作者：程序员Sunday · [Sunday面试指南](https://note.lgdsunday.club/)
>
> [在线阅读与配图](https://note.lgdsunday.club/agent/q698-haystack-components-pipelines-agents/) · [题库目录](../../README.md)

*下面是一段教学用的模拟面试对话。*

🧑‍💻 面试官：Haystack 里的 Pipeline，就是把几个函数按顺序调用吗？

🙋‍♂️ 我：它会把组件连接起来，但还可以包含分支、循环，以及依赖允许时的异步执行。

🧑‍💻 面试官：检索器返回 documents，下一组件却要求 messages，只要都写了类型就能连起来？

🙋‍♂️ 我：还要看输入输出的名称和类型是否匹配，需要时增加转换。

🧑‍💻 面试官：那么 Agent 达到最大步数停了，Pipeline 收到返回值，是不是就能当作任务成功？

> 组件连得上、流程跑完了、任务完成了，要分开确认；连接契约和停止原因都会影响下游判断。

## 面试速答（60 秒版）

Haystack 是用于构建检索、RAG 和 Agent 等 AI 应用的框架，核心做法是把功能封装成组件，再通过 Pipeline 连接它们的输入与输出。

Component 完成某项具体工作，比如检索文档、构造提示词或调用模型。Pipeline 规定组件之间怎样传数据，可以包含分支和循环，并不只是一条从头走到尾的直线。

Agent 也是可以组合进系统的组件。它通过支持工具调用的模型，反复获取信息和执行工具，并按停止条件结束。需要固定处理的外层流程，可以包住局部需要模型判断的 Agent。

使用时要检查组件连接的字段名称、类型和运行条件，同时保留 Agent 的停止原因。达到执行上限和拿到有效答案是不同结果，不能只看方法有没有正常返回。

## 知识点详解：先看数据怎样交接，再看谁决定下一步

### Component 把一项功能的入口和出口说清楚

假设一个文档问答系统包含检索、重排和回答生成。

检索组件接收问题，输出文档列表；重排组件接收问题和候选文档，输出重新排列的文档。接下来还需要把文档组织成模型能使用的消息，才能交给生成组件。

这里不能只说“上一个组件的结果传给下一个”。开发者需要明确传的是哪个输出，以及下游哪个输入接收它。[官方组件说明](https://docs.haystack.deepset.ai/docs/components)专门列出了输入、输出与独立运行的方式。

### Pipeline 的连接是数据依赖，不是看图猜执行顺序

两个组件画得一左一右，并不能说明它们已经正确连接。需要建立输出到输入的连接，让框架知道下游什么时候拿到了必需数据。

例如检索器输出 `documents`，重排组件也接收 `documents`，名称和类型都要核对。文档列表不能直接冒充对话消息，需要有明确的转换步骤。

同一个问题也可以交给两个检索分支，再合并候选结果。同步执行与异步执行的并行能力不同，因此，图上存在独立分支，不等于同步调用会自动并行。[Pipeline 文档](https://docs.haystack.deepset.ai/docs/pipelines)区分了这些执行方式和依赖条件。

![组件连线，必须对上输入和输出](https://note.lgdsunday.club/img/Q698/02-haystack-input-output.webp)

### Agent 可以放进 Pipeline，Pipeline 也可以成为工具

有些任务的路径很明确，比如解析文件、清洗、切片、写入索引。另一些任务需要结合当前结果继续判断，比如先查制度，证据不足时再查产品说明。

前一类适合由 Pipeline 规定主要路径。后一类可以让 Agent 在有限工具中选择，再把结果交回外层流程。

如果有一段已经稳定的检索流水线，也可以通过对应工具封装供 Agent 使用。这并不意味着模型能任意修改流水线内部连接。模型选择的是工具，工具内部仍可以是固定流程。

这样组合的好处，是不用把原来每个稳定步骤都重新交给模型决定。但要同时观察外层流程和内层工具调用，否则一次失败可能只留下“Agent 没答出来”，却看不见是哪一段检索出了问题。

![固定流水线，也能成为 Agent 工具](https://note.lgdsunday.club/img/Q698/03-haystack-composition.webp)

### 有返回值以后，还得看为什么停下来

以核验时的 Haystack 3.2 [Agent 文档](https://docs.haystack.deepset.ai/docs/3.2/agent)为例，Agent 可以使用工具、保存运行状态，并按退出条件或执行步数上限停止。

假设目标是找到某条合同的有效版本。模型输出了一段文字，与真的找到了指定版本，不能等同。达到步数上限也只说明运行被限制住了，不能作为“没有合同”的证据。

因此，下游可以分别处理正常完成、工具失败、预算耗尽和需要人工接手，不能把所有返回都接到“发送成功回答”上。运行状态中的字段，也不一定自动变成模型能读到的消息，要核对具体工具与状态映射。

验收时，可以先使用固定文档与假的检索组件，检查字段交接、空结果、错误分支和退出条件，再接入真实模型。本文核对框架机制，没有实际部署文档库或运行模型，不提供未经测量的吞吐量结论。Haystack 的原生实现是 Python，不能把其他语言的同名 Pipeline 当作官方对照实现。

## 面试官继续追问

### Pipeline 中出现循环，就一定是 Agent 吗？

不一定。开发者规定“校验失败再执行一次”的循环，仍然可以是预设控制流程。判断是否采用 Agent，要看运行中的动作选择是否交给模型，而不是图上有没有回边。

### 连线合法，为什么结果还是不对？

类型兼容只保证数据能交接。例如两边都是文档列表，但上游可能给的是旧版本，或者缺少权限过滤。需要检查文档身份、过滤条件与实际证据，不能把业务语义交给类型名称证明。

### 怎样限制循环造成的消耗？

设置合理的步骤或运行次数上限，并在耗尽时给下游明确状态。再记录每次返回了什么、为什么继续，区分证据不足与反复调用同一工具。上限是最后的保护，不能代替停止判断。

## 面试速记卡

> - Component 完成具体工作，输入输出有明确字段与类型。
> - Pipeline 连接数据依赖，可以包含分支和循环。
> - 同步流程有分支，不代表组件会自动并行执行。
> - Agent 可以嵌入 Pipeline，稳定流水线也能封装成工具。
> - 正常返回、达到步数上限、完成业务目标，需要分别判断。
