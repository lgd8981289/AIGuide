### 追加问题：`/note/` 与 `note.` 两个同时做行不行（2026-10-07 傍晚）

**线上实测**：`www.lgdsunday.club/note` 与 `/note/` 均 301 → `note.lgdsunday.club/`；note 站 canonical 自指；主站 robots 不含 /note；note 站 robots 声明自己的 sitemap-index。即当前是**方向相反的单宿主**。

**结论：不建议**。核心认知纠正是「双跑 ≠ 双倍曝光」——同一份内容两个 host 会被聚成一簇，**只留一个代表 URL、其余过滤**（Google 官方原文："search engines will generally take one version and filter the others out"），数学是 1+1=1，且**留谁由引擎决定**。

**三种形态**（已写入 `docs/seo-subdomain-vs-subdirectory.md` 第十一节）：
- **A 双跑互不指认**：引擎自选 canonical。note. 是「老站」（有 sitemap/历史）、主域名路径是「新站」（零外链）→ 选中谁不可控；最坏分支是 note. 赢，**比现状更差**。已查证 Google 官方博客记录的真实翻车案例（Glenn Gabe：Google 把 staging 子域名的 URL 选为 canonical，原始页面被顶掉）。
- **B 双跑 + 跨域 canonical**：三处硬伤——① canonical 官方定性为 hint（"a canonical is a hint, not a rule"）；② **本仓库做不到只让一边指认**：canonical 由构建时 `SITE.url` 生成，一份 dist 挂两个 host 会输出同一个 canonical，等于其中一侧每页自我否定；要各自自指就得两份构建 = 形态 A；③ note 站现有 sitemap 列了 496 条自己的 URL，会与 canonical 打架。
- **C 单宿主 + 301**：唯一正确的「两个地址都能用」。

**一句话**：「两个地址都能用」≠「两个地址都放内容」。C 方案下 note. 照样能访问（名片、公众号菜单、旧外链全部有效），只是跳转到 `/note/`，用户浏览器无感、引擎只认一个。

**只有这套配置才有的损失**：即使强行双跑，note 侧也是半残 —— Bing 侧 note 属性日额度为 0、抓取统计返回空数组，双跑时那 496 个 URL 依然推不上去。双跑的 note 侧 ≈ 一份「存在但不被搜到」的副本。

**唯一允许两边都活**：① 迁移过渡期（301 收敛期，几周）；② 两个 host 承载不同内容（那就不是同一个站两个地址了）。

**落到动作**：保留 note. 的 DNS 与证书（301 需长期有效，用户入口不能断）；内容宿主只能有一个。当前方向是反的（`/note` 301 到子域名）。
